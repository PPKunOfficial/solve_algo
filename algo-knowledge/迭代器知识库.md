# Rust 迭代器知识库

这份笔记以 `src/bin/` 里的 LeetCode 题解为例。目标不是记住所有方法，而是先判断**元素是如何交给闭包的**，再把「变形、筛选、聚合」串起来。

## 1. 一条迭代器链的骨架

```rust
let result: Vec<_> = source
    .iter()                  // 取得元素
    .filter(|item| predicate(item)) // 保留符合条件的元素
    .map(|item| transform(item))    // 变形
    .collect();              // 消费迭代器，收集结果
```

- **迭代器适配器（懒执行）**：`map`、`filter`、`enumerate`、`zip`、`flat_map`、`windows`、`split` 等；只描述处理流程，不立即遍历。
- **消费适配器（触发执行）**：`collect`、`count`、`sum`、`fold`、`find`、`max` 等；调用后真正遍历，并且迭代器不能再用。
- 类型通常可由上下文推导；推导不出来时标注终点即可：`let sum: i32 = iter.sum()`、`collect::<Vec<i32>>()`。

> 读闭包时从外到内看：先确认迭代项类型，再看模式匹配是否解引用，最后看返回值类型。

---

## 2. 三种最常用的起点：所有权与借用

假设 `nums: Vec<i32>`：

| 写法 | 单个元素类型 | `nums` 后续可用？ | 适用场景 |
| --- | --- | --- | --- |
| `nums.iter()` | `&i32` | 可以 | 只读、可能还要使用原向量 |
| `nums.iter_mut()` | `&mut i32` | 可以 | 原地修改每个元素 |
| `nums.into_iter()` | `i32` | 不可以，所有权被移走 | 最终不再需要原向量，避免复制 |

```rust
let total: i32 = nums.iter().sum();              // `sum` 能对 &i32 求和
let doubled: Vec<i32> = nums.iter().map(|&x| x * 2).collect();
let owned: Vec<i32> = nums.into_iter().filter(|x| *x > 0).collect();
```

`String` 等非 `Copy` 元素尤要留意：`words.iter()` 的元素是 `&String`，而 `words.into_iter()` 的元素是 `String`。不要为“让编译器通过”无脑 `clone()`；先决定是否真的要消耗容器。

## 3. 闭包参数里的 `&` 到底在干什么

`iter()` 会产出引用，因此闭包参数常出现一层或多层 `&`。

```rust
nums.iter().map(|&x| x * 2)       // 输入是 &i32；`&x` 解出 Copy 的 i32
nums.iter().filter(|&&x| x > 0)   // filter 又把迭代项借用给谓词：输入为 &&i32
```

`filter` 的谓词接收 `&Self::Item`，所以：

| 上游产出 | `filter` 闭包参数 | 典型写法 |
| --- | --- | --- |
| `i32`（如 `into_iter()`、范围） | `&i32` | `filter(|x| **x > 0)` 或 `filter(|&x| x > 0)` |
| `&i32`（如 `iter()`） | `&&i32` | `filter(|&&x| x > 0)` |

若解引用符号让代码难读，优先写清楚模式，或直接使用自动解引用可调用的方法：`filter(|(_, word)| word.contains(x))`。

## 4. 本目录题解中已经用到的组合

### `iter + map + filter + count`：嵌套扫描

[`1365-有多少小于当前数字的数字.rs`](../leetcode/rust/src/bin/1365-有多少小于当前数字的数字.rs)：

```rust
nums.iter()
    .map(|&x| nums.iter().filter(|&&y| y < x).count() as i32)
    .collect()
```

- 外层 `map`：为每个 `x` 生成一个答案。
- 内层 `filter`：保留小于 `x` 的 `y`。
- `count`：消费内层迭代器，得到数量。
- 外层 `collect`：把每个数量收成 `Vec<i32>`。

这是 $O(n^2)$ 的直接解；同一 `nums` 被只读借用两次，合法且没有复制数组。

### `iter + enumerate + filter + map`：筛选元素的下标

[`2942-查找包含给定字符的单词.rs`](../leetcode/rust/src/bin/2942-查找包含给定字符的单词.rs)：

```rust
words.iter()
    .enumerate()
    .filter(|(_, word)| word.contains(x))
    .map(|(index, _)| index as i32)
    .collect()
```

- `enumerate()` 把 `item` 变成 `(usize, item)`。
- `filter` 保留原元组；`map` 再只取索引。
- 下标默认是 `usize`，题目返回值需要 `i32`，所以在这里转换。

### `iter + zip + flat_map`：交错两段序列

[`1470-重新排列数组.rs`](../leetcode/rust/src/bin/1470-重新排列数组.rs)：

```rust
nums[..n]
    .iter()
    .zip(&nums[n..])
    .flat_map(|(&x, &y)| [x, y])
    .collect()
```

- `zip` 把两条流配对为 `(&i32, &i32)`；长度以较短的一侧为准。
- 闭包返回 `[x, y]`；`flat_map` 把每对产生的两个元素摊平成一条流。
- 若用 `map(|(&x, &y)| [x, y])`，结果会是 `Vec<[i32; 2]>`，而不是目标的 `Vec<i32>`。

### `for_each`：原地副作用

[`448进阶做法-找到所有数组中消失的数字.rs`](../leetcode/rust/src/bin/448进阶做法-找到所有数组中消失的数字.rs)：

```rust
(0..nums.len()).for_each(|i| {
    let index = nums[i].abs() as usize - 1;
    nums[index] = -nums[index].abs();
});
```

`for_each` 是消费适配器，适合“对每项执行动作”。这里迭代的是索引范围而非 `nums.iter_mut()`，因为每次要根据当前值写入**另一个**位置；这种索引写法避开了同时持有相互冲突的借用。

随后：

```rust
nums.into_iter()
    .enumerate()
    .filter_map(|(i, num)| if num > 0 { Some((i + 1) as i32) } else { None })
    .collect()
```

`filter_map` 相当于 `filter` 与 `map` 的合体：`Some(value)` 产出值，`None` 丢弃值。它避免先创建一层 `Option` 再额外展开。

### `into_iter + fold`：显式维护状态

[`485-最大连续-1-的个数.rs`](../leetcode/rust/src/bin/485-最大连续-1-的个数.rs)：

```rust
nums.into_iter()
    .fold((0, 0), |(curr, max), x| {
        if x == 1 { (curr + 1, max.max(curr + 1)) } else { (0, max) }
    })
    .1
```

`fold(初始累加器, 更新函数)` 每次返回下一轮累加器。这里 `(curr, max)` 是“当前连续长度、历史最大值”。

适用判断：遍历过程需要前一轮状态、最终只要一个结果时，先考虑 `fold`。如果能用 `sum`、`max`、`count` 等专用终点，则专用方法更直白。

### `split + map + max`：按分隔条件切片

[`485n-最大连续-1-的个数.rs`](../leetcode/rust/src/bin/485n-最大连续-1-的个数.rs)：

```rust
nums.split(|&n| n == 0)
    .map(|segment| segment.len())
    .max()
    .unwrap_or(0) as i32
```

- `split` 产生多个切片 `&[i32]`，分隔元素不包含在结果里。
- 连续的 `0` 会产生空切片；`len()` 自然为 `0`。
- `max()` 的结果是 `Option<usize>`，因为输入可能为空；`unwrap_or(0)` 给出题目所需的空输入默认值。

### `windows + find + map`：相邻元素关系

[`645-错误的集合.rs`](../leetcode/rust/src/bin/645-错误的集合.rs)：

```rust
let dup = nums.windows(2)
    .find(|w| w[0] == w[1])
    .map(|w| w[0])
    .unwrap();
```

- `windows(2)` 产生重叠窗口：`[a, b]`、`[b, c]`、……；窗口元素是借用原数组的切片。
- `find` 返回第一个满足条件的 `Option<&[i32]>`。
- `map` 只在 `Some` 时取重复值。
- 本题保证重复值存在，因此可 `unwrap()`；没有题目保证时，用 `?`、`unwrap_or` 或返回 `Option` 处理缺失情况。

同文件的 `sum`：

```rust
let sum: i32 = nums.iter().sum();
let exp: i32 = (1..=nums.len() as i32).sum();
```

范围 `1..=n` 是闭区间，包含 `n`；`sum` 需要知道输出类型，因此显式写 `i32`。

### `collect` 收集为集合，再在范围上筛选

[`448-找到所有数组中消失的数字.rs`](../leetcode/rust/src/bin/448-找到所有数组中消失的数字.rs)：

```rust
let hash_nums: HashSet<i32> = nums.into_iter().collect();
(1..=n).filter(|x| !hash_nums.contains(x)).collect()
```

同一个 `collect()` 根据目标类型收集为不同容器：前者由变量注解推导为 `HashSet<i32>`，后者由函数返回类型推导为 `Vec<i32>`。`HashSet::contains` 接收引用，所以范围迭代器传给 `filter` 的 `&i32` 可直接传入。

### `map` 可返回新元组或 `Vec`

`map` 的闭包可以返回任意类型；终点 `collect()` 根据目标类型把每轮返回值收集起来。

```rust
let nums = vec![1, 2, 3];

let pairs: Vec<(i32, i32)> = nums.iter()
    .map(|&x| (x, x * x))
    .collect();
// [(1, 1), (2, 4), (3, 9)]

let groups: Vec<Vec<i32>> = nums.iter()
    .map(|&x| vec![x, x * 2])
    .collect();
// [[1, 2], [2, 4], [3, 6]]
```

第二段使用 `map`，所以每轮产出的 `Vec<i32>` 会保留为一个元素，最终是嵌套的 `Vec<Vec<i32>>`。若目标是把每轮产生的小序列直接拼平，改用 `flat_map`：

```rust
let flattened: Vec<i32> = nums.iter()
    .flat_map(|&x| vec![x, x * 2])
    .collect();
// [1, 2, 2, 4, 3, 6]
```

因此：`map(|x| (..))` 通常收成 `Vec<(..)>`；`map(|x| vec![..])` 收成 `Vec<Vec<_>>`；`flat_map(|x| vec![..])` 收成已拍平的 `Vec<_>`。这正是 1470 题中 `flat_map(|(&x, &y)| [x, y])` 的作用。

## 5. 常用方法速查

| 目标       | 方法            | 产出              |
| -------- | ------------- | --------------- |
| 逐项变形     | `map`         | 新迭代器            |
| 保留符合条件的项 | `filter`      | 新迭代器            |
| 变形且可丢弃   | `filter_map`  | 新迭代器            |
| 带下标遍历    | `enumerate`   | `(usize, item)` |
| 两流配对     | `zip`         | `(left, right)` |
| 一对多并摊平   | `flat_map`    | 新迭代器            |
| 查第一个匹配项  | `find`        | `Option<item>`  |
| 计算数量     | `count`       | `usize`         |
| 计算总和     | `sum`         | 指定数值类型          |
| 取最大/最小项  | `max` / `min` | `Option<item>`  |
| 自定义累计状态  | `fold`        | 累加器             |
| 收成容器     | `collect`     | 由目标类型决定         |

## 6. 做题时的选择顺序

1. **需要保留原数组吗？** 要：`iter()`；不要：`into_iter()`；要原地改：`iter_mut()` 或索引。
2. **每个元素独立变换吗？** 用 `map`。
3. **有些元素要丢掉吗？** 只判断用 `filter`；变换结果本身是 `Option` 用 `filter_map`。
4. **需要下标、两数组对应项、相邻项或分段吗？** 分别看 `enumerate`、`zip`、`windows`、`split`。
5. **最后要什么？** 容器用 `collect`，计数用 `count`，和用 `sum`，极值用 `max/min`，状态机用 `fold`。
6. **终点可能没有结果吗？** `find/max/min` 返回 `Option`；只有题目保证存在时才用 `unwrap()`。

---

## 7. 高频坑

- `map`、`filter` 不会执行到结果被消费：漏写 `collect()`、`count()` 等，逻辑根本没有跑。
- `filter` 只保留原元素，不改变元素。既要改变又要丢弃，选 `filter_map`。
- `zip` 不会报长度不等，会静默截断到短侧；题目不保证等长时要先处理。
- `usize` 与 `i32` 不能混用。索引、`len()`、`enumerate()` 都是 `usize`；按边界转换，别在整条链里反复 `as`。
- 迭代器是一次性的：`let it = nums.iter(); it.count(); it.count()` 不可行。需要再次遍历就重新创建迭代器。
- `into_iter()` 之后容器已被移动；若仍要使用原容器，改用 `iter()`，不要盲目克隆。
- 不要把有副作用的任务硬塞进 `map`；需修改外部状态时用 `for_each`，能用纯变换链时仍优先 `map`。

## 8. 一句口诀

**借用选 `iter`，消费选 `into_iter`；变形 `map`，过滤 `filter`，可选值 `filter_map`；最后一定用 `collect/count/sum/fold` 收尾。**
